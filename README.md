# Vietnamese History Knowledge Graph & RAG System

This project focuses on constructing a **Knowledge Graph (KG)** from Vietnamese History textbooks (specifically Grade 12) and implementing a **Retrieval-Augmented Generation (RAG)** system to answer questions based on the constructed graph.

## 🚀 Overview

The system processes unstructured text from textbooks to extract entities and relationships, building a structured Knowledge Graph. This graph is then loaded into a **Neo4j** database. A RAG pipeline is implemented to query this knowledge base, providing accurate answers to history-related questions.

## 📂 Project Structure

- **`extract/`**: Module containing the logic for **Entity Extraction**.
    - `main.py`, `entity_processor.py`, etc.: Core logic for identifying and extracting entities from text.
- **`Extract_kg/`**: Module containing the logic for **Relationship Extraction** and **Knowledge Graph Construction**.
    - `kg_builder.py`, `relationship_processor.py`, etc.: Core logic for linking entities and building the graph.
- **`benchmark_extract.ipynb`**: Jupyter Notebook to run the **Entity Extraction** process. It utilizes the code in the `extract/` folder.
- **`benchmark_extract_kg.ipynb`**: Jupyter Notebook to run the **Relationship Extraction** and **KG Construction** process. It utilizes the code in the `Extract_kg/` folder.
- **`SGK/`**: Contains the source documents (e.g., `SGK_Lich_Su_12_Ket_Noi_Tri_Thuc.txt`) and related assets.
- **`outputs/`**: Directory for general generated output files.
- **`entities/`**: Directory generated by `benchmark_extract.ipynb` containing:
    - `entities_*.json`: The extracted entities file.
    - `request_statistics_*.json`: Statistics about the extraction process.
- **`knowledge_graph_historical_v2.json`**: The final Knowledge Graph output generated by `benchmark_extract_kg.ipynb`.
- **`kb-kg.ipynb`**: The main Jupyter Notebook for RAG implementation and evaluation.
- **`load_neo4j.py`**: Python script to load the generated graph data (JSON format) into a Neo4j database.
- **`RAG Evaluation Report.html`**: Report containing the evaluation metrics of the RAG system.

## 🛠️ Prerequisites

- **Python 3.8+**
- **Neo4j Database**: You need a running instance of Neo4j (Desktop or AuraDB).
- **GPU**: Recommended for running Large Language Models (LLMs) for extraction and RAG.
- **Google Gemini API Key**: Required for the extraction pipeline (configured in `config.py` files or environment variables).

## 📦 Installation

1.  **Clone the repository:**
    ```bash
    git clone <repository-url>
    cd KLTN
    ```

2.  **Install dependencies:**
    The project relies on several Python libraries including `langchain`, `transformers`, `neo4j`, and `sentence-transformers`.
    ```bash
    pip install langchain langchain-community transformers sentence-transformers faiss-cpu neo4j python-dotenv accelerate bitsandbytes google-generativeai
    ```

3.  **Environment Setup:**
    Create a `.env` file in the root directory to configure your Neo4j credentials and API keys:
    ```env
    NEO4J_URI=bolt://localhost:7687
    NEO4J_USERNAME=neo4j
    NEO4J_PASSWORD=your_password
    GOOGLE_API_KEY=your_gemini_api_key
    ```

## 🏃‍♂️ Usage

### 1. Entity Extraction
Run the **`benchmark_extract.ipynb`** notebook.
- **Purpose**: Extracts entities (People, Organizations, Events, etc.) from the source text files in `SGK/`.
- **How it works**: It uses the modules in the `extract/` folder to process text windows and identify entities using the Gemini API.
- **Output**: Creates a new folder **`entities/`** containing:
    - `entities_<timestamp>.json`: The list of unique extracted entities.
    - `request_statistics_<timestamp>.json`: Performance metrics of the extraction process.

### 2. Knowledge Graph Construction
Run the **`benchmark_extract_kg.ipynb`** notebook.
- **Purpose**: Extracts relationships between the entities found in step 1 and builds the full Knowledge Graph.
- **How it works**: It uses the modules in the `Extract_kg/` folder. It reads the latest entity file (configure `ENTITY_FILE` in `Extract_kg/config.py` if needed) and processes the text again to find connections.
- **Output**: Generates **`knowledge_graph_historical_v2.json`** (or the filename specified in `Extract_kg/config.py`).

### 3. Load Data into Neo4j
Once the JSON graph data is generated, use the provided script to import it into your Neo4j database.

**Important**: Check `load_neo4j.py` and ensure the filename in `loader.load_data_from_json(...)` matches your generated KG file (e.g., `knowledge_graph_historical_v2.json`).

```bash
python load_neo4j.py
```
*Note: This script will clear existing data in the database before loading the new graph.*

### 4. Run RAG & Evaluation
The `kb-kg.ipynb` notebook contains the RAG pipeline. Run the relevant sections to:
- Initialize the GraphRAG system.
- Query the system with natural language questions.
- Evaluate the performance using the provided test sets (`questions_500.txt`, `question_1000.txt`).

## 📊 Evaluation

The system includes an evaluation module that generates reports (e.g., `RAG Evaluation Report.html`) assessing the accuracy and relevance of the answers provided by the RAG system.
